# Phase 1 / M1 — Reproducible environment

M1 proves that a Docker Compose environment can be started, restored, verified, captured, and
destroyed automatically — and that repeating the cycle yields byte-identical initial state. Agents,
tool brokering, state diff, and graders are intentionally out of scope.

## Acceptance criteria

- [x] `EnvironmentDriver` protocol and `EnvironmentHandle` (`src/reprocase/environments/`).
- [x] Support World minimal service: health endpoint, deterministic `app.reset` restore command,
      `app.export_state` state export, stdlib-only image on `python:3.12-slim`
      (`examples/support-world/`).
- [x] `docker_compose` environment variant in `environment.yaml` (`compose` / `restore` /
      `healthcheck` / `state` sections); the `fake` driver is unchanged.
- [x] Compose safety precheck rejects privileged mode, host network/PID/IPC, docker socket mounts,
      host root/home/workspace bind mounts, added capabilities, and unpinned remote includes.
- [x] Compose lifecycle via `docker compose` argv only (never a shell): dynamic project name
      `reprocase_<slug>_<suffix>`, dynamic host ports injected through a per-run env file,
      `up -d --wait` → restore → healthcheck → capture → collect logs →
      `down --volumes --remove-orphans`.
- [x] State capture canonicalization: JSON parse → declared `remove_paths` dropped → declared
      arrays sorted → canonical JSON (UTF-8, sorted keys, no whitespace) → SHA-256 digest.
- [x] Internal diagnostic CLI `reprocase env-check <case-or-env.yaml> --cycles N`.
- [x] Distinct stable failure codes with `ENVIRONMENT_ERROR` attribution: `ENV_COMPOSE_UNSAFE`,
      `ENV_COMPOSE_INVALID`, `ENV_START_FAILED`, `ENV_RESTORE_FAILED`, `ENV_HEALTHCHECK_FAILED`,
      `ENV_STATE_CAPTURE_FAILED`, `ENV_STATE_INVALID`, `ENV_TEARDOWN_FAILED`.
- [x] 20 consecutive cycles produce 20 identical state digests
      (`tests/test_env_acceptance.py`, marked `slow` + `docker`).
- [x] Zero residual containers, networks, or volumes after every cycle (asserted in tests).
- [x] M0 fake flow, tests, ruff, and mypy-strict remain green.

## Compose lifecycle semantics

Each cycle runs an isolated Compose project named `reprocase_<slug>_<run-suffix>`:

```text
prepare
  -> allocate one ephemeral host port per compose.port_variables entry
  -> write ports to <work_root>/<project>/compose.env
  -> docker compose config --format json  (validates and renders the file)
  -> safety precheck on the rendered config (skip with --allow-unsafe)
start
  -> docker compose up -d --wait
restore
  -> docker compose exec -T <service> <restore.command...>   (deterministic reset)
healthcheck
  -> poll the configured URL with ${PORT_VAR} substitution until timeout
capture
  -> docker compose exec -T <service> <state.capture.command...>
  -> parse single JSON document, canonicalize, digest
collect logs
  -> docker compose logs --no-color  ->  <work_root>/<project>/environment.log
teardown
  -> docker compose down --volumes --remove-orphans
```

Guarantees and rules:

- Teardown always runs, even when an earlier step fails; a teardown failure is reported with the
  project name and a manual cleanup command, and never masks the primary failure.
- Volumes are deleted on every teardown, so no state can leak between cycles.
- Host ports are never hardcoded in `compose.yaml`; the runner allocates ephemeral ports per cycle
  and passes them through the dedicated env file, keeping parallel runs possible later.
- All canonicalization rules (`remove_paths`, `sort_arrays_by`) live in `environment.yaml` and are
  covered by a `canonicalization_digest`, so the ignore rules are part of the evidence.
- Restore failures, healthcheck timeouts, invalid capture output, and teardown failures map to
  distinct `FailureCode`s with `ENVIRONMENT_ERROR` attribution; they are never agent failures.

## Verification

```bash
uv run reprocase env-check examples/support-world/environment.yaml --cycles 20
uv run pytest -m "docker and slow"   # 20x acceptance with residual-resource assertions
uv run pytest                        # full suite (docker tests skip without a daemon)
```

Observed result: 20/20 cycles returned
`sha256:5189f4f2dd66c9edf848040762f2492c2569a99f6dcccec3bf9511e2f868c753`, and
`docker ps -a` / `docker network ls` / `docker volume ls` filtered by `reprocase` were empty after
every cycle. The 20-cycle acceptance completes in roughly four minutes on a warm image.

With M1 the environment lifecycle can claim reproducibility level **R1** for the initial state;
`reprocase run` still executes only the fake M0 flow until M2 wires the driver into the
orchestrator.
