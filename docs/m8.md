# M8 — LLM Agent and Dual Models

## Goal

Give Acme Support World its first real brain: a self-owned foundational LLM agent
(no framework adapter) speaking OpenAI-compatible Chat Completions with tools,
stdlib-only (`urllib`), zero new runtime dependencies. It is the enabling
capability for M9's failure-discovery and model-comparison work.

## Shape and loop

`examples/acme-world/agents/llm_agent.py`, a python-adapter entrypoint:

```text
system = task instruction + visible policy summary (task.context)
tools  = Tool Broker registry projection (name/description/input_schema
         ↔ OpenAI function tool format; fields are isomorphic)
loop:  model → tool_calls → broker.call(name, arguments) → results appended
        → ... → final message (AgentResult.output.message)
```

The projection comes from `ToolBroker.tool_definitions()` (added in this milestone).

## Dual-model configuration (two env-var sets)

```bash
# primary set (REPROCASE_LLM_PROFILE=primary, the default)
export REPROCASE_LLM_BASE_URL=https://api.deepseek.com/v1
export REPROCASE_LLM_API_KEY=sk-...
export REPROCASE_LLM_MODEL=deepseek-chat

# secondary set (REPROCASE_LLM_PROFILE=secondary)
export REPROCASE_LLM2_BASE_URL=https://api.openai.com/v1
export REPROCASE_LLM2_API_KEY=sk-...
export REPROCASE_LLM2_MODEL=gpt-4.1-mini
```

- `REPROCASE_LLM_PROFILE` ∈ {`primary`, `secondary`} selects the set (default `primary`).
- Any missing required variable fails fast at agent start, naming the missing vars.
- Which model runs is **runtime configuration, not EvalCase content**: the case digest
  does not change with the model; attributability comes from `agent.model` in the run result.

## Key discipline (exit criterion)

- The API key only ever travels in the HTTP `Authorization` header — never in messages,
  tool arguments, events, or results.
- **Defense in depth**: the runner collects the concrete values of every `REPROCASE_*_API_KEY`
  env var (`_env_secret_values()`) and value-scrubs **every** event payload and the persisted
  `agent_output` (`scrub_secrets`: recursive substring replacement with `[REDACTED]`).
  Even a model that echoes the raw key into free text after a prompt injection cannot leak
  it into evidence.
- `test_secret_scrubbing_survives_model_echoing_the_key` proves this end to end with a
  scripted response that literally outputs the key: zero leakage across events.jsonl /
  result.json / report.html.

## Usage and model identity (exit criterion)

- After each model response the agent reports that call's token usage via
  `context.emit({"usage": ...})` (the runner routes it as an `agent.model.usage` event,
  so per-call usage lands in the evidence stream).
- Totals land in `RunResult.usage` (`model_calls` / `input_tokens` / `output_tokens`);
  **unknown stays null, never fabricated as zero**: if any response lacks a usage block,
  the totals are null.
- `AgentResult.model` (new field) → `RunResult.agent.model` (observed identity).
  The manifest is written before the run and records the declared identity (model null);
  the run result carries the observed one.

## Budget enforcement (exit criterion)

The model loop is naturally bounded by the Broker: every tool call consumes the
`max_tool_calls` budget. When the budget is exhausted the broker rejects the call;
the agent catches `ToolCallError(AGENT_BUDGET_EXCEEDED)` and **returns gracefully**,
so the primary failure is `AGENT_BUDGET_EXCEEDED` (same semantics as scripted agents).
`test_budget_exhaustion_is_primary_agent_failure` proves it: `max_tool_calls=3` plus a
model that loops tool calls forever → FAIL with exactly that code.

## Determinism semantics (R1)

Model non-determinism is a feature, not a bug — verdict determinism comes from graders.
Acceptance uses two agent layers that never mix: deterministic reference/wrong scripted
agents for the pass/fail matrix; the LLM agent for failure discovery and model comparison.

## Wired cases

- `examples/acme-world/refund-smoke-llm.yaml` — the standard ORD-1001 refund, graded
  exactly like `refund-smoke` (refund created, customer notified, bystanders unchanged,
  policy tests).
- `examples/acme-world/refund-overdue-llm.yaml` — the overdue fixture (ORD-1001 past the
  30-day window) where **the correct behavior is to decline**: no refund, no email, order
  untouched. A model that "finds a way" fails outright. This is the first substrate for
  explainable dual-model differences.

## Retry and error handling

- Simple linear retry: 2 retries (sleep 1s, 2s) on 429/5xx/network errors; other 4xx
  fails immediately.
- Malformed tool arguments from the model (non-JSON / non-object) → the agent raises →
  attributed AGENT_FAILURE; nothing is silently swallowed.
- API unreachable after retries → agent failure (the model is part of the agent's
  implementation, so the failure belongs to the agent domain).

## Explicitly out of scope

Framework adapters, multi-trial statistics, model gateways, retry tuning. The ≥3-run
dual-model acceptance on real APIs (exit criteria ① and ④) needs real keys and network;
it belongs to release hardening before M9 and is not CI-covered. CI covers every
mechanical path via a scripted OpenAI-compatible server.

## Known boundaries

- `urllib` has no connection pooling: one connection per request. Fine for the base loop;
  revisit if M9 needs high-frequency calling.
- The fake flow (`adapter: fake`) does not run the LLM agent; LLM cases must use the
  python adapter.
- The base loop is strictly sequential (one tool call batch per turn); concurrent tool
  calls are future work.
