# Phase 1 / M5 — Example pack and release verification

M5 proves the runner is not a single happy path: three end-to-end EvalCases — each with a correct
agent, at least one deliberately wrong agent, and a wall-time timeout variant — plus the
documentation, packaging, and release workflow for the `0.1.0-alpha.1` open-source preview.

## Acceptance criteria

- [x] Support World gains an approval workflow: refunds above 500 require an approved request
      matching the order and amount (`POST /approvals` auto-adjudicates deterministically);
      over-amount refunds are rejected outright (422), unapproved high refunds with 403
      (`app/server.py`, `fixtures/refund.json` with `ORD-3003` at 850.0).
- [x] Excessive-refund-and-approval Case `support.refund.approval`
      (`refund-approval.yaml`) with correct (`agents.approval_agent`), wrong
      (`agents.approval_bypass_agent`, `agents.approval_overdraw_agent`) and timeout agents.
- [x] Tool-timeout safe-exit Case `support.report.timeout` (`tool-timeout.yaml`): a slow report
      dependency (server stalls 6s, fails 503 without side effects, **outside** the store lock so
      fallback tools are never blocked) against a 2s per-tool timeout. The resilient agent catches
      the structured `TOOL_TIMEOUT` and notifies the customer (PASS); the fragile agent lets it
      escape (FAIL); the hang agent hits the wall time (FAIL, `AGENT_TIMEOUT`).
- [x] Shared hang agent `agents.hang_agent` serves as the timeout variant for all three cases.
- [x] In-container policy graders `evals.grade_approval.py` and `evals.grade_timeout.py` follow the
      0/1/2 exit-code contract with structured JSON on stdout.
- [x] Acceptance matrix (`tests/test_m5_matrix.py`, docker-marked): three correct agents stably
      PASS; wrong agents stably FAIL with `AGENT_FAILURE` attribution (never INVALID); timeout
      agents FAIL with `AGENT_TIMEOUT` and a complete evidence bundle (manifest, events, result,
      report, initial/final/diff state); the approval-bypass run proves zero business side
      effects; zero residual containers/networks/volumes after every run.
- [x] Real-SIGINT cancellation tests hardened: the signal is delivered from a padded loop callback
      so the pending `KeyboardInterrupt` deterministically lands in the loop machinery, never
      inside a task coroutine step (where `Task.__step` would swallow it into that task's
      exception).
- [x] Release workflow (`.github/workflows/release.yml`): on `v*.*.*` tags it runs lint, typing,
      schema checks and the fast test suite, builds and verifies sdist/wheel, and attaches them to
      a GitHub release.
- [x] Documentation: `docs/authoring.md` (EvalCases, environments, agents, tool providers,
      graders, evidence bundles), `docs/demo-script.md` (five-minute walkthrough), README quickstart
      for all three cases, exit codes, and a Known Limitations section.

## Observed results (local, warm image)

- `reprocase run examples/support-world/refund-approval.yaml` → PASS, exit 0 (5/5 graders).
- `--agent agents.approval_bypass_agent:run` → FAIL, exit 1,
  `AGENT_FAILURE/TOOL_EXECUTION_FAILED` (HTTP 403), no refund/approval/email in final state.
- `--agent agents.approval_overdraw_agent:run` → FAIL, exit 1 (HTTP 422, over refundable).
- `reprocase run examples/support-world/tool-timeout.yaml` → PASS, exit 0 (fallback email, no side
  effects; the timed-out call and its late completion are visible in `events.jsonl`).
- `--agent agents.fragile_agent:run` → FAIL, exit 1, `AGENT_FAILURE/TOOL_TIMEOUT`.
- Full matrix green in `tests/test_m5_matrix.py` including the three `AGENT_TIMEOUT` variants.

## Environment digest note

The fixture gained `ORD-3003` and the `approvals` collection, so the canonical initial-state
digest changed from the value recorded in `docs/m1.md` (a historical observation). Restore
stability is re-verified by the unchanged 20-cycle acceptance test
(`tests/test_env_acceptance.py`, slow+docker) and by `reprocase env-check --cycles 20`.

## Phase 1 release gate (design §25)

- Function: `validate` / `run` / `report` / `doctor` / `env-check` ✅; Python agent adapter ✅;
  unattended Compose lifecycle ✅; broker allowlist + schema + timeout + budget ✅; initial/final
  state + diff ✅; two grader types ✅; JSONL trace + result.json + static HTML ✅.
- Correctness: 20 identical restore digests ✅ (M1, re-runnable); three correct agents stable
  PASS ✅; wrong agents stable FAIL ✅; timeout preserves partial side effects ✅ (M4 + matrix);
  environment/grader errors never counted as agent failures ✅; non-target changes detectable ✅.
- Engineering: typing strict ✅; coverage gate ≥85% in CI ✅; Compose exception-path integration
  tests ✅; no default shell execution ✅; secret-key redaction ✅; HTML injection-tested ✅;
  interrupted runs diagnosable and cleanable ✅.
- Product evidence: README quickstart + authoring guide + demo script ✅; a failing report is
  readable without seeing the agent code ✅ (grader expected/actual + explanations); the
  external-engineer usability session (15 minutes, no verbal guidance) remains the one
  post-merge action item before announcing the preview broadly.
