# Phase 1 / M2 — Deterministic evaluation loop

M2 connects the M1 Compose environment to deterministic grading: initial state → scripted actor →
final state → JSON diff → graders → verdict. Scripted Actors are fixed-step test fixtures, not real
agent adapters (those arrive in M3 with the Tool Broker).

## Acceptance criteria

- [x] Initial/final `StateRecorder` writing canonical `state.initial.json` / `state.final.json`
      whose artifact sha256 equals the reported content digest (`recording/state.py`).
- [x] RFC 6902-style JSON diff with `from_value` on `replace`, tagged
      `reprocase.state-diff/v0` (`recording/diff.py`); diffs show both target and non-target entity
      changes.
- [x] Grader protocol, full `GraderResult` (grader_type, score, expected, actual, evidence,
      assertions, grader_digest, duration_ms) and all-pass verdict engine:
      environment/runner/grader ERROR → INVALID; agent exception → FAIL; any grader FAIL → FAIL;
      all PASS → PASS (`graders/`, `runner/orchestrator.py::_verdict`).
- [x] `StateAssertionGrader`: RFC 6901 pointers, operators `eq`/`not_eq`/`exists`/`absent`/
      `contains`/`gte`/`lte`/`unchanged`/`changed`/`length_eq`, per-assertion results, explicit
      `tolerance` required for float `eq`/`not_eq` (otherwise the assertion is an ERROR)
      (`graders/state_assertion.py`).
- [x] `TestCommandGrader`: argv execution inside a Compose service without a shell; exit-code
      semantics 0 → parse stdout JSON, 1 → FAIL, 2–125 → ERROR, timeout/unstartable/invalid output
      → ERROR; raw stdout/stderr stored as content-addressed artifacts
      (`graders/test_command.py`).
- [x] Scripted Actor loader (`module:function` entrypoints resolved against the environment
      directory) and the Compose flow wired into `reprocase run` (`runner/scripted.py`,
      `runner/orchestrator.py`).
- [x] Standard refund EvalCase plus four actors: correct, wrong order, missing email, excessive
      (policy-violating) refund (`examples/support-world/refund.yaml`, `agents/`,
      `evals/grade_refund.py`).
- [x] PASS / FAIL / INVALID / evidence acceptance matrix (`tests/test_run_compose.py`).
- [x] Content-addressed artifact store (`recording/artifacts.py`); grader stdout/stderr and
      environment logs land in the evidence bundle.
- [x] Final state is captured before any grader executes (§11.5).
- [x] Zero residual containers/networks/volumes after every run (asserted per test).

## Compose run semantics

```text
validate
  -> prepare (safety precheck, dynamic ports, compose.env)
  -> up -d --wait --build
  -> restore (deterministic reset command)
  -> healthcheck (HTTP poll)
  -> capture initial state            (state.initial.json)
  -> run scripted actor (host process, HTTP against the mapped service URL)
  -> capture final state              (state.final.json, before any grader runs)
  -> diff initial vs final            (state.diff.json)
  -> run graders sequentially         (state assertions in-process, test commands via exec)
  -> collect environment logs
  -> down --volumes --remove-orphans  (always, even on failure)
  -> verdict + result.json
```

Rules carried from the design:

- Actor exceptions are attributed `AGENT_FAILURE/AGENT_EXCEPTION`; the runner still captures the
  final state and runs graders so partial side effects remain visible.
- Environment and grader failures produce `INVALID`, never an agent FAIL.
- Every failing grader reports structured `expected`, `actual`, `explanation`, and `evidence`
  (state pointers or artifact digests) — the data basis for the later agent-feedback projection.
- Test commands may mutate state; final state is always captured first and graders are expected to
  be read-only.
- `--build` on `up` keeps the image in sync with the build context; layer caching keeps warm
  cycles fast.

## CLI

```bash
uv run reprocase run examples/support-world/refund.yaml                      # correct actor → PASS (exit 0)
uv run reprocase run examples/support-world/refund.yaml --agent agents.wrong_order:run      # → FAIL (exit 1)
uv run reprocase run examples/support-world/refund.yaml --agent agents.missing_email:run    # → FAIL (exit 1)
uv run reprocase run examples/support-world/refund.yaml --agent agents.unapproved_refund:run # → FAIL (exit 1)
```

`--agent` overrides the case entrypoint (scripted adapter only). Compose runs claim
reproducibility level **R1** in both manifest and result; fake runs stay R0.

## Known boundaries (deferred)

- No Tool Broker, allowlists, or budget enforcement (M3).
- No agent timeout/cancellation semantics beyond best-effort (M4).
- Actor entrypoint modules are imported in-process and cached by name; two worlds exporting the
  same module name in one runner process share the first import (fixture-level limitation).
- The refund EvalCase lives at `examples/support-world/refund.yaml` (not `evals/`) because the M1
  loader forbids `..` references escaping the case directory; `evals/` holds in-container grader
  modules only.
