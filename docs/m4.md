# Phase 1 / M4 — Failure evidence and run resilience

M4 makes failures explainable: bounded cancellation, best-effort grading, primary/secondary
failures, hardened artifacts, redaction, a static HTML report, and `report`/`doctor` CLI.

## Acceptance criteria

- [x] Two-phase agent wall time: `asyncio.wait` + explicit cancel, then a bounded cancellation
      grace period (5s). An agent that swallows `CancelledError` past the grace period is still
      attributed `AGENT_FAILURE/AGENT_TIMEOUT`, plus a runner warning — the run continues
      collecting evidence (in-process coroutines cannot be force-killed; semantics documented
      below).
- [x] Ctrl-C leaves a diagnosable run: `RUN_CANCELLED` failure, `CANCELLED` status, CLI exit 4,
      shielded teardown retry, and `cleanup_required` + manual cleanup command when teardown
      could not finish.
- [x] Best-effort grading (§12.3): agent failures never abort evidence collection; a failed
      final-state capture degrades state-dependent graders to `SKIPPED` and the run to INVALID —
      never a fabricated business FAIL. In-container test commands still run.
- [x] Primary/secondary failures (§16.2): teardown failures land in `secondary_failures` and
      never rewrite the verdict (verdict logic excludes `ENV_TEARDOWN_FAILED`); they set
      `cleanup_required` + `cleanup_command` and make the CLI print an infrastructure warning and
      exit 3.
- [x] ArtifactStore writes are owner-only (`0o600`); state snapshots, environment logs, and the
      HTML report too. Environment logs are truncated to the last 10 MiB with an in-file marker
      and a run warning (§18).
- [x] `output.redaction.keys` from the EvalCase extends one run-level redaction policy applied to
      broker events, agent events, and `result.json`'s `agent_output` (closing the M3 deferral);
      the report inherits it through the already-redacted evidence. The report carries the §17.2
      sensitive-data notice.
- [x] Static single-file HTML report with all ten §15 sections (identity incl. code digests and
      git state, verdict + attribution incl. secondary failures, budgets/usage, graders with
      expected/actual, state digests, collapsible diff, event timeline, warnings, artifact links,
      reproduction level + rerun command). All dynamic text is HTML-escaped; no external
      dependencies, no template engine.
- [x] `reprocase report <run_dir>` regenerates the report from evidence;
      `reprocase doctor` checks Python/Docker/Compose/working-directory and lists stale
      `reprocase_*` compose projects with manual cleanup commands (never auto-deletes).
- [x] Tech debt: `reprocase.runner` re-export is now lazy, eliminating the latent circular import
      through `graders/__init__` (subprocess regression test).

## Cancellation semantics

```text
agent runs as a task
  -> asyncio.wait(wall_time): completed? normal classification
  -> expired: task.cancel()
  -> asyncio.wait(grace=5s): settled? AGENT_TIMEOUT
  -> still running: AGENT_TIMEOUT + "ignored cancellation" warning
     (the orphaned task may keep running in-process; it gets a courtesy
     second at loop shutdown — never a blocking wait)
```

Runner-level guarantees (hardened in the M4 review round):

- The compose flow runs on a **private loop with a bounded shutdown**; result persistence never
  depends on loop teardown completing (an immortal agent cannot block `result.json`).
- The broker has a **closed state**: the moment the agent phase ends — normally, on timeout, or
  on runner cancellation — late tool calls are rejected and recorded, so abandoned agent code
  cannot mutate the final state or the grading inputs.
- On runner cancellation the shutdown order is owned by the flow itself: close broker → cancel
  agent with a bounded wait → collect logs → teardown. The loop runner cancels only the main
  coroutine; it never fans cancellation out to tasks the flow owns.
- An agent that raises `CancelledError` itself (or awaits a cancelled subtask) is an ordinary
  `AGENT_EXCEPTION` — never confused with a runner cancellation.
- Teardown runs as a **single task** with bounded observe-only waits (they neither re-raise its
  error nor forward cancellation to it); a SIGINT mid-teardown re-waits the same task (30s
  grace) and still ends as `RUN_CANCELLED` / exit 4 — never two concurrent `compose down`s.
- Lifecycle errors (start/restore/healthcheck/provider-load) are recorded **before** any cleanup
  failure, so `primary_failure` stays the earliest conclusion-blocking error; teardown failures
  land in `secondary_failures` with `cleanup_required` + manual command.
- Environment logs are collected best-effort in the `finally` **before** teardown — including on
  failed starts and cancellations, where they matter most.

## Redaction

One run-level redaction policy (default keys ∪ `output.redaction.keys`) is applied before
anything is persisted: broker event payloads (arguments and results), agent events
(`agent.completed`, `agent.message`), and `result.json`'s `agent_output`. The real tool
invocations always see the unredacted values — redaction only affects records. The HTML report
inherits the policy because it renders only the already-redacted evidence.

## Rerun command

The report's rerun command is assembled from the cwd-relative case path recorded at run time
(`case.relative_path`), plus `--agent` when an override was used (`agent.entrypoint_override`)
and `--seed` when non-zero, with shell quoting — copying it re-runs the same execution.

## Known boundaries (deferred)

- Cancellation is cooperative; a CPU-bound agent that never awaits cannot be interrupted at all
  (strong isolation needs a separate agent runtime, post-Phase-1). An orphaned agent task that
  outlives its grace period is abandoned at loop shutdown after a courtesy second — bounded,
  never blocking result persistence.
- `secondary_failures` carry full details; deep cross-referencing of failure → event sequence is
  left for later evidence tooling.
- Grader `expected`/`actual` payloads are not redacted (they come from the eval author, not the
  agent); agent-controlled text in them is escaped in the report.
- `reprocase doctor` reports stale projects but never deletes them by design (§12.4).
