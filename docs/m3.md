# Phase 1 / M3 — Real agent execution

M3 connects real (still trusted, host-process) Python agents to the M2 evaluation loop through a
Tool Broker that enforces allowlists, argument schemas, per-tool timeouts, and call budgets.
Scripted actors from M2 keep working unchanged.

## Acceptance criteria

- [x] `AgentAdapter` protocol, `AgentContext` (run_id, seed, fixed_clock, tool_names, emit) and
      `AgentResult` (output, summary, usage) (`agents/protocol.py`); `PythonAgentAdapter` loads
      async `module:function` entrypoints and normalizes raw returns (`agents/python_adapter.py`).
- [x] `Tool` / `ToolProvider` / `ToolRegistry` (`tools/protocol.py`, `tools/registry.py`);
      providers build tools from the `EnvironmentHandle` (dynamic service URLs).
- [x] `ToolBroker` chain in exact design order: allowlist → JSON Schema argument validation →
      atomic budget decrement → `tool.call.started` → per-tool timeout → serializability check +
      key redaction → `tool.call.completed` / `tool.call.failed`; rejections emit
      `tool.call.rejected` and never reach the environment (`tools/broker.py`).
- [x] JSON Schema validation via the `jsonschema` package (new runtime dependency; listed in
      design §5.1 and unavoidable for correct draft-compliant validation).
- [x] Per-tool timeout (`asyncio.wait_for` → `TOOL_TIMEOUT`) and `max_tool_calls` budget consumed
      at call start without an intervening await, so timed-out/failing calls still count.
- [x] Agent wall time via `asyncio.timeout`; timeout → `agent.timed_out` event +
      `AGENT_FAILURE/AGENT_TIMEOUT` attribution, then final state capture and grading continue.
- [x] Agent events: `agent.started/completed/failed/timed_out/message/model.usage`;
      `agent_output` and structured `usage` (tool_calls counted; unknown model metrics stay null)
      land in `result.json`.
- [x] Python agents wired into the Compose flow next to scripted actors; manifest components and
      `Usage` recorded; `--seed` on `reprocase run`.
- [x] Support World Tool Provider (`tools.support_api:create_tools`: customer.get / order.get /
      refund.create / email.send), correct and wrong Python agents, and `refund-agent.yaml`.
- [x] End-to-end matrix (`tests/test_run_agent.py`): PASS, FAIL, unauthorized-tool rejection,
      invalid-arguments isolation, budget and wall-time attribution, zero residuals.

## Broker semantics

- Agents only ever see the broker (`tools.call(name, arguments)`); raw `Tool` objects stay with
  the runner.
- Before the agent starts, every provider-supplied tool is validated (name format, JSON Schema
  legality via `check_schema`, allowlist references resolvable). Provider or case defects surface
  as `CASE_ERROR` and make the run INVALID — never agent business failures.
- Every rejection raises a structured `ToolCallError` to the agent — agents may catch it and
  continue; if it escapes, it becomes the run's `AGENT_FAILURE` with the original code
  (`TOOL_NOT_ALLOWED`, `TOOL_ARGUMENT_INVALID`, `AGENT_BUDGET_EXCEEDED`, ...). Errors carrying a
  non-agent attribution are re-raised untouched so they cannot be re-labeled.
- A budget that is silently absorbed (agent catches the rejection) still produces an
  `AGENT_FAILURE/AGENT_BUDGET_EXCEEDED` failure record at the end of the agent phase.
- Wall-time expiry is distinguished from agent-side `TimeoutError`s via `asyncio.timeout`'s
  `expired()`: only a genuinely expired timer is attributed `AGENT_TIMEOUT`; an SDK raising
  `TimeoutError` is an ordinary `AGENT_EXCEPTION`.
- Event payloads — including `agent.completed` output — are redacted by key (`authorization`,
  `cookie`, `token`, `password`, `api_key`) before being written; redaction recurses dicts,
  lists, and tuples. Note `result.json`'s `agent_output` intentionally keeps the raw value
  (field-level output redaction is M4 scope, see `output.redaction`).
- Tool results must be JSON-serializable; anything else is a structured tool failure.

## Import isolation

Entrypoint loading and execution both run inside a reentrant `ImportIsolation` context
(`entrypoints.py`) that the orchestrator holds for the whole span: provider load → provider
execution (`create_tools`) → adapter load → agent run. On entry it shadows every cached module
whose top-level package exists in the case root and puts the root on `sys.path`; on exit it
evicts everything imported during the span and restores the shadowed modules. Function-body
relative imports (`from .helper import x`), absolute self-imports (`from agents.helper import
x`), and dynamic `importlib.import_module(...)` calls therefore always resolve against the case's
own root — even when the host process already has a same-named package cached (the foreign
package is restored byte-identical afterwards). Validation-only loads keep using a short-lived,
load-scoped isolation.

Every entrypoint module is also origin-checked level by level along its dotted name: each level
must resolve to a concrete file inside the import root (`__file__` present and
`is_relative_to(root)`). A typo'd, missing, or namespace-package entrypoint — or one colliding
with an installed dependency — is rejected with `CASE_ENTRYPOINT_INVALID` instead of silently
falling back to host code, keeping eval cases self-contained. In-container grader commands
(`python -m evals.grade_refund`) are argv executed inside the container and never pass through
this loader.

## R1 identity

The manifest records the effective agent adapter and entrypoint (including `--agent` overrides),
the tool provider, and a content digest of their code (module file, or the whole package when the
module lives in one, always with paths relative to the import root), plus the git commit and
dirty-worktree flag when available (§6.4). Changing agent or provider source therefore changes
the run's R1 identity even when the case digest is unchanged.

## Known boundaries (deferred)

- Agents are trusted host code; nothing stops a malicious agent from bypassing the broker
  (strong isolation is a later Agent Runtime milestone).
- Coroutine cancellation on wall-time timeout is cooperative, not forced termination.
- No framework adapters (OpenAI Agents SDK, LangGraph), no multi-trial, no LLM judges.
- `fixed_clock` is accepted in `AgentContext` but always `None` in M3 (time control arrives with
  later reproducibility work).
- Entrypoint loading and execution are isolated per case root (see "Import isolation" above).
  Because the mechanism mutates process-global import state, cases that share top-level package
  names must run **sequentially** in one process — the CLI runs one case at a time; concurrent
  in-process runs of same-named packages are not supported.
- Entrypoint modules must be self-contained inside the case directory (origin check above).
  External dependencies must be provided through the environment image or a future explicit
  declaration mechanism; none exists yet.
